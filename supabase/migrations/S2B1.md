2. Ejecutar manualmente el archivo SQL completo en Supabase SQL Editor del entorno de

3. Correr las consultas read-only del final del archivo: anon/authenticated false,

4. Desplegar y probar Preview. Las nuevas escrituras fallan cerrado con 503 si falta RPC.
5. Publicar backend + panel juntos después de revisión. No mezclar panel viejo con API

No revertir sólo al backend viejo: volvería a habilitar escrituras no protegidas.
La RPC es aditiva y puede permanecer si se suspende la publicación.

## Reglas

Nueva → Contactando/Cotizado/Confirmado/Cancelado; Contactando → Cotizado/Confirmado/Cancelado;
Cotizado → Confirmado/Cancelado; Confirmado → Completado/Cancelado.
Confirmado requiere reserva registrada. Confirmación de reserva valida cotización vigente,
con disponibilidad distinta de no, y aceptación/link si corresponde.
Completado/Cancelado no se reabren. Repetir estado sin transición es seguro.
Sync no reabre cerradas. Cancelar reserva bloquea comisiones paid y waived.
Ambas rutas de cancelación usan la misma transacción.

La RPC bloquea solicitud y reserva y valida el estado esperado dentro de la transacción.
No llama a Google ni Resend. Un fallo SQL revierte toda la operación.
No hace reparación automática de inconsistencias históricas.
No incorpora S2B-2 ni S2B-3: una respuesta de red perdida conserva la incertidumbre habitual;
revisar/refrescar antes de repetir, no afirmar rollback si sólo se perdió la respuesta HTTP.

## Pruebas

`npm run check` y `npm test` no requieren servicios.
Integración real sin dependencias Node, con Docker y Postgres local desechable:

```sh
docker run -d --rm --name listo-s2b-test -e POSTGRES_PASSWORD=local-test postgres:16
LISTO_S2B_POSTGRES_CONTAINER=listo-s2b-test npm test
docker stop listo-s2b-test
```

Esperar que Postgres esté listo. El test recrea la base **listo_s2b_test** dentro del
contenedor indicado. Nunca señalar un contenedor/base compartidos o de producción.
El esquema de prueba usa las tablas comerciales documentadas. Los tests verifican
bloqueos reales, permisos y rollback mediante un trigger que falla sólo en esa base.

## Smoke test (sólo registros de prueba)

- Confirmar una cotización válida; reserva y solicitud deben quedar confirmadas.
- Completar; sync/confirm no deben devolverla a Confirmado.
- Dos pestañas: avanzar en una; intentar cambiar/contactar desde la vieja → conflicto.
- Cancelar desde booking y desde selector de inquiry: ambas tablas cambian juntas.
- Comisión pagada/exenta: cancelar se rechaza, sin cambios.
- Cerrada: ningún retroceso; misma transición cerrada no-op.
- Recargar panel y comprobar las filas antes de repetir una operación con error de red.
